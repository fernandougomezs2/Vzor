# v0.4.2-D compare and schema-drift audit

## Scope and unchanged contracts

This subphase changes only private Rust orchestration for comparison and schema
drift. Package version remains `0.3.2`; `output_version = 1` and
`format_version = 1` are unchanged. Public APIs, comparison statuses and
codes, drift codes and severities, deterministic order, report/HTML/CLI/agent
outputs, persistence, dependencies, hasher, GIL, threading, Arrow, Polars,
and unsafe code are unchanged.

## Pre-D pipeline audit

For one public `compare(before, after)` call, Python normalized `before` once
and `after` once. The binding created one `DatasetInput`, profile, and observed
schema for each side, then one `ComparisonResult`. The Python layer then built
the required owned report dataclasses and snapshots. There was no repeated
normalization or profiling inside that individual call.

For one public `schema_drift(before, after)` call, the same two normalizations,
inputs, profiles, and observed schemas were made. It then built an owned
`ComparisonResult` (including every before/after snapshot) only to derive a
small `SchemaDriftResult` and discard the comparison. Separate public compare
and drift calls necessarily remain separate: no global cache or state was
introduced.

## Post-D pipeline

`comparison::visit_comparison_columns` is a private, deterministic O(B + A)
factual traversal. It retains the existing name lookup maps and visits BEFORE
columns in order followed by AFTER-only columns in order.

- `compare()` uses it to produce its required owned `ComparisonResult`.
- The retained internal observed-schema drift helper can derive drift from the
  same factual traversal without snapshots.
- The public `schema_drift()` binding uses a narrower structural input path:
  it validates column lengths and numeric type errors, counts nullability, and
  compares only presence, logical type, and nullability. It deliberately skips
  unique counts, numeric statistics/ranges, observed values, observed schemas,
  and owned comparison snapshots because drift does not expose or interpret
  them.

The numeric validator is shared with profiling, so malformed private binding
input retains its existing numeric type error behavior. The structural path
preserves issue order and severities exactly.

## Ownership

The public comparison result still necessarily owns its column name, snapshots,
and change vector because Python exposes all of them after the inputs are gone.
Schema drift now owns only its emitted issue names and codes; it no longer
allocates `ObservedDatasetSchema`, `ColumnComparison`, or snapshot strings only
to discard them. `DatasetInput` for before and after still coexist during a
call because both are needed to compare the two DataFrames.

## Equivalence coverage

New public tests cover unchanged and row-count-only inputs; additions,
removals, logical type changes, both nullability directions, unique-count,
range, observed-value, reorder-only, rename, and multiple simultaneous changes.
They cross-check factual comparison status against drift issues, severities,
and canonical order. A Rust test verifies direct schema drift and the owned
comparison-derived path yield identical output on mixed structural changes.

## Benchmarks

All measurements use two isolated repetitions on Windows 10.0.26200, AMD
Ryzen 7 7730U (16 logical CPUs), 15.343 GiB RAM, CPython 3.12.10, pandas 3.0.5,
and the fixed baseline Parquet fixture. Times exclude input loading; peak is
the maximum working set.

| Workload | Pre-D: s / rows/s / peak | Post-D final: s / rows/s / peak | Delta |
| --- | --- | --- | --- |
| 100k compare | 6.167 / 17,234 / 426,229,760 B | 3.573 / 27,991 / 424,169,472 B | -42.1% s, +62.4% rows/s, -0.5% peak |
| 100k schema_drift | 3.930 / 25,448 / 426,188,800 B | 3.921 / 25,518 / 417,488,896 B | -0.2% s, +0.3% rows/s, -2.0% peak |
| 1M compare | 48.279 / 21,128 / 2,864,730,112 B | 53.307 / 18,828 / 2,851,028,992 B | +10.4% s, -10.9% rows/s, -0.5% peak |
| 1M schema_drift | 40.670 / 24,699 / 2,859,122,688 B | 41.320 / 24,220 / 2,783,141,888 B | +1.6% s, -1.9% rows/s, -2.7% peak |

The 1M timings have meaningful isolated-process variability. The historical
v0.4.1 figures (~138 s compare and ~65 s drift) are not credited to D: the
pre-D measurements already include A/B/C. D's reproducible functional result
is removal of drift-only profile/schema/snapshot allocations; its measured
working-set reduction is modest because pandas normalization and the two owned
`DatasetInput` values remain dominant. The post-D 1M compare time regression
is recorded as an observed benchmark regression, not attributed as a benefit.

## Remaining debt

The next explicitly authorized optimization should investigate the shared
pandas/PyO3 construction of the two normalized inputs, which dominates
large-row compare and drift calls. Do not add a public cache or begin v0.4.2-E
without a new scope decision.
