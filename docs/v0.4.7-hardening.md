# Vzor v0.4.7 — Fuzzing, Documentation & Release Hardening

## Scope and non-goals

This final v0.4 hardening phase strengthens verification only. It introduces no
public API, no feature, no data transformation, and no performance-oriented
runtime redesign. `output_version = 1` and `format_version = 1` remain stable.
The only runtime-source edit removes a redundant PyO3 borrow identified by
Clippy; it leaves the same bound object, behavior, and data path in place.

## Rust fuzz-equivalent property targets

`cargo-fuzz` was evaluated but is not present in the supported Windows
development environment, whose installed Rust toolchain is stable only.
Adding a nightly/libFuzzer execution requirement would not strengthen the
CPython compatibility matrix. Instead, the project uses `proptest 1.11.0`
(`MIT OR Apache-2.0`) as a test-only dependency. It runs directly through the
existing `cargo test --locked` CI step, is not linked into the extension or
wheels, and uses a fixed seed `0x565A4F520407` with 96 cases per target.

`crates/vzor-core/src/hardening_tests.rs` exercises only normalized Rust
models and core functions. It does not invoke PyO3, Python, filesystem, or
network APIs. Its bounded targets cover:

- integer profile count/unique/statistical ordering invariants;
- finite-statistics behavior for arbitrary float bit patterns;
- string count and unique bounds;
- `compare(x, x)` and `schema_drift(x, x)` identity invariants;
- validation against a suggested schema derived from the same categorical input;
- first-appearance ordering of distinct invalid categorical values;
- malformed column-length rejection without panic; and
- total, repeatable handling of arbitrary persistence-parser input.

Hypothesis was intentionally not added. The broad combinatorial coverage is at
the Rust ownership boundary where inputs are normalized, while compact Python
regressions continue to prove the public adapters, CLI, and presentation
contracts. That keeps local and CI execution fast without a second property
framework or a runtime dependency.

## Public edge regressions

`tests/test_release_hardening.py` verifies extreme finite/non-finite floats,
empty values, integers, booleans, Unicode strings, categorical and datetime
columns through public APIs. It adds deterministic standalone HTML checks for
inspection, validation, comparison, and drift using hostile column names;
malformed persistence JSON through the CLI with stdout/stderr separation; and
repeated mixed-type profile/validation/compare/drift results.

Existing tests retain duplicate-name rejection, integer overflow boundaries,
empty/all-null frames, cross-backend parity, CLI usage errors, path Unicode and
spaces, HTML write errors, persistence version errors, and bounded report
representation contracts.

## Audit result

The panic scan found runtime `expect` calls only where the immediately
preceding guards establish a non-empty numeric collection; the added property
targets continuously exercise that invariant. Clippy identified one redundant
borrow in the PyO3 iterator construction. The minimal removal is behaviorally
neutral and makes `cargo clippy --all-targets -- -D warnings` clean.

No panic, overflow, nondeterminism, incorrect unique bound, ordering defect,
HTML escaping defect, persistence error leak, or API regression was found by
the local hardening suite. Remote CPython/platform and wheel evidence is
recorded in the v0.4.0 release checklist after its CI gate completes.
