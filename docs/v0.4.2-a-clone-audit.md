# v0.4.2-A internal clone audit

`DatasetInput` owns every normalized `ColumnInput` and its
`Vec<ProfileValue>`. A derived `Clone` therefore duplicates the vector and all
owned string payloads.

This subphase changes `profile_structure` to borrow `&DatasetInput`. The
bindings for `observed_schema`, `suggest_schema`, `inspect`, and the shared
observed-schema helper now profile the one original input and retain it for
observed-value extraction. `suggested_schema_from_observed` continues to derive
only from the observed schema.

`DatasetInput` and `ColumnInput` no longer implement `Clone`, so a future
call site cannot silently restore this deep-copy path.

Remaining, intentional copies are result ownership: profile column names and
logical types, retained observed values (at the existing cardinality limit),
and suggested allowed values. Exact unique counting still clones strings into
its `HashSet`; Python normalization, GIL behavior, transport, Arrow, buffers,
and comparison/drift work are explicitly deferred to later v0.4.2 subphases.
