# v0.4.4 cross-backend parity and efficient buffers

## Pre-change audit

Both adapters ultimately pass columns to PyO3, which builds an owned Rust
`DatasetInput` containing `Vec<ProfileValue>`. That ownership boundary means
no Python/NumPy/Polars buffer can safely outlive the call. Before this phase,
pandas signed integers, floats and non-null booleans iterated their original
Series through PyO3; other pandas dtypes used Python normalization generators.
Polars used a generator and normalization call for every dtype and value.

| Backend / dtype | Source and pre-route | Final route | Classification |
| --- | --- | --- | --- |
| pandas signed int, float, non-null bool | pandas Series, PyO3 scalar iteration | existing raw scalar path | one-copy into Rust `Vec<ProfileValue>` |
| pandas nullable, string/object, categorical, datetime | extension/object values and generator | checked fallback | multi-object conversion; correctness path |
| Polars signed int, UInt8/16/32, float, non-null bool | Polars Series scalar iteration and generator | direct raw scalar path | one-copy into Rust `Vec<ProfileValue>` |
| Polars UInt64, nullable numeric/bool, string, categorical/enum, date/datetime, Null | Polars Series scalar iteration | checked fallback | multi-object conversion; correctness path |

There is no zero-copy or borrowed view path. No NumPy buffer API, Polars Arrow
buffer, PyArrow dependency, `unsafe`, or GIL release was introduced. The
Polars improvement removes the Python generator/normalizer call on a safe
subset; it does not claim native-buffer transport.

## Parity and semantics

The explicit cross-backend matrix covers signed/unsigned integers, Float32/64,
Boolean and nullable Boolean, nullable integer, pandas object strings and
String, categorical and Polars Enum, Date, Datetime, all-null/Null, NaN,
infinities and negative zero. Public profile, observed schema, suggested
schema, inspect, validation, mixed compare and mixed drift remain equivalent
where the source data has the same logical meaning.

Null masks remain represented by the checked fallback: null becomes Vzor Null.
Polars NaN uses the raw float conversion and becomes Vzor Null, consistently
with pandas. Infinities remain non-null and excluded from numeric statistics.
UInt64 always uses the checked fallback so values beyond i64 raise the existing
overflow error. Datetime remains the safe `isoformat()` fallback; timezone
buffer semantics are deliberately deferred. Strings and categories remain
owned Rust strings in first-seen order; no unique-count algorithm changed.

Sliced pandas Series and sliced Polars DataFrames are covered by tests. The
raw scalar path is safe for slices because it makes no contiguity/view claim;
it iterates values and Rust owns its result.

## Benchmarks

All values are isolated local single-run measurements except the pandas 1M
profile recheck, which is a two-run median. They are environment measurements,
not universal backend claims. JSON evidence is in `C:\VzorBenchmarks` under
`after_044_*.json`.

| Case | Backend | Vzor seconds | Rows/sec | Peak MiB |
| --- | --- | ---: | ---: | ---: |
| 100k baseline profile | pandas | 1.679 | 59,550 | 276.1 |
| 100k baseline profile | Polars | 0.794 | 125,989 | 245.6 |
| 100k baseline inspect | pandas | 1.655 | 60,436 | 275.6 |
| 100k baseline inspect | Polars | 0.877 | 114,004 | 246.3 |
| 1M baseline profile (recheck) | pandas | 17.713 | 56,456 | 1,706.9 |
| 1M baseline profile | Polars | 14.413 | 69,383 | 1,449.7 |
| 1M baseline inspect (recheck) | pandas | 25.989 | 38,647 | 1,701.8 |
| 1M baseline inspect | Polars | 15.663 | 63,846 | 1,454.7 |
| 1M numeric profile | Polars | 4.244 | 235,611 | 623.3 |
| 1M many_nulls profile | Polars | 6.046 | 165,397 | 920.1 |
| 1M categorical profile | Polars | 1.205 | 829,746 | 381.5 |
| 1M heavy_strings profile | Polars | 6.850 | 145,986 | 2,465.3 |

Against v0.4.3, Polars numeric changed from 4.624 s / 623.5 MiB to 4.244 s /
623.3 MiB. Categorical remains effectively unchanged (1.218 to 1.205 s;
381.1 to 381.5 MiB), as expected from fallback. The first pandas 1M profile
single run was 32.283 s; its two-run recheck was 17.713 s, so it is documented
as environmental variance rather than a regression. Pandas inspect rechecked
at 25.989 s versus 24.989 s in v0.4.3 (about 4.0% slower): this small change is
within a one-session benchmark comparison, and no pandas adapter code changed.
No 5M test was run.

## Verification and deferred work

New tests cover raw/fallback classification, null masks, UInt64, sliced frames,
Unicode and public parity. The complete suite preserves deterministic output,
HTML/repr, public API and `__all__`. Package version remains `0.3.2`,
`output_version = 1`, and `format_version = 1`; no mandatory runtime dependency
was added and Polars remains optional.

Deferred to a separately approved v0.4.5 investigation: an allocation-profiled
typed buffer model, null bitmap transport, timestamp transport, categorical
dictionary transport, and any Arrow C Data Interface or zero-copy proposal.
