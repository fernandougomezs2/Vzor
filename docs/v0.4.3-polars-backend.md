# v0.4.3 Polars backend

Vzor 0.3.2 now accepts a materialized `polars.DataFrame` in every existing
Python API: profile, observed schema, suggested schema, inspect, validate,
compare, and schema drift. The public models, report repr, HTML, output and
persistence formats are unchanged. Mixed pandas/Polars compare and drift are
supported because both normalize to the same private Rust input.

## Installation and imports

Polars is an optional extra: `pip install "vzor[polars]"`. The declared lower
bound is `polars>=1.0`, the first stable major series providing the DataFrame,
dtype, categorical, enum, temporal and direct iteration APIs used here. It is
MIT licensed. Vzor never imports Polars at package import time, and pandas
continues to work when Polars is absent. No PyArrow dependency is added.

## Adapter design

`_frame_adapter.normalize_dataframe` dispatches private pandas and Polars
normalizers. The Polars normalizer reads each `Series` directly and yields the
same normalized columns consumed by PyO3; it never calls `to_pandas()`.
This intentionally uses scalar iteration/copying for correctness and parity;
Arrow/zero-copy transport is deferred to v0.4.4.

## Dtype and value policy

Int8/16/32/64 and UInt8/16/32/64 map to `integer`; Float32/64 to `float`;
Boolean to `boolean`; String to `string`; Categorical and Enum to
`categorical`; Date and all Datetime units/time zones to `datetime`; and Null
to `unknown`. UInt64 values must fit i64 or raise the established overflow
error. Polars null and floating NaN are Vzor null; infinities remain non-null.
Empty strings, `"NULL"`, `"NaN"`, `"None"`, and Unicode strings are values.
Categorical/Enum observations retain the established first-seen order and
50-value policy. Date/datetime scalar rendering is internal only and does not
alter public output semantics.

`polars.LazyFrame`, Series, Arrow Tables, dicts, and lists are rejected. Vzor
does not collect LazyFrame implicitly and does not configure Polars threads.

## Verification and limitations

Tests cover the dtype matrix, all-null data, NaN/infinities/-0.0, UInt64,
Unicode, categorical observations, validation/persistence-compatible schemas,
mixed-backend compare/drift, deterministic repr, and HTML. The CLI remains
pandas-based. Benchmarks record `backend` and support Polars profile/inspect;
they are measurements of this scalar adapter, not a claim of universal Polars
performance superiority.
